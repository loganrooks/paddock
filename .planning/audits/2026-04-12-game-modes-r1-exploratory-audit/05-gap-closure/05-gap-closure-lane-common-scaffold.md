# 05 Gap Closure Lane Common Scaffold

## Shared framing

These lanes are not blank ideation lanes.

They are substantive closure lanes for the remaining mature-product operating-model gap that survived:

- whole-job verification
- the verifier-side mature-product context pass
- the handoff-underframing review
- the 05-gap-closure synthesis

They should preserve settled Round 2A / Round 2B doctrine and only close what remains genuinely open.

## Shared classification and launch intent

Unless a lane spec explicitly says otherwise, this bundle should be treated as:

- `initial architecture research/planning`

Default launch policy:

- `gpt-5.4`
- `xhigh`

Reason:

- these lanes are still exploratory and planning-facing
- they are canon-sensitive and may still change rerun-input doctrine
- they are not checker-style repair passes or narrow verification lanes

## What every lane must preserve

- private-first product center
- substrate-plus-wrappers posture
- layered memory and cadence doctrine
- staged visibility and audience-right distinctions
- non-foreclosure seams already established in Round 2B

These are governing inputs, not topics to casually reopen.

## Shared traceability contract

Every lane output must:

- state which `handoff-relative gaps` it helps answer
- state which `emergent audit-revealed gaps` it helps answer
- distinguish inherited doctrine from new closure work
- identify which sources are steering versus background-only
- explicitly say what it is not answering
- name downstream consequences for:
  - mature-product synthesis
  - later sensitivity pass
  - canon patching, where relevant

## Shared epistemic rules

- Do not overclaim from suggestive references.
- Do not treat external examples as direct blueprints.
- Do not let one good example harden into one mandatory future.
- Distinguish:
  - doctrine already settled
  - plausible options still alive
  - recommended carry-forward
  - explicit deferral
- If a lane uses earlier repo research outside this audit, mark it as background unless the lane itself re-engages it directly enough to rely on it.

## Shared output sections

Every substantive lane output should include:

1. `Lane framing`
2. `Traceability and scope`
3. `What is already settled`
4. `Path of inquiry`
5. `Core closure questions`
6. `Findings`
7. `Live options or operating shapes`
8. `Recommended carry-forward`
9. `Explicit deferrals`
10. `What the later sensitivity pass must test from this lane`
11. `Coverage note`

## Output tone

Outputs should be:

- concrete
- planning-facing
- explicit about uncertainty
- comparative where useful

They should not read like:

- generic product essays
- generic growth advice
- one-sided advocacy for a favorite future
