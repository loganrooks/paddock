# 05 Sensitivity Docket Common Scaffold

## Shared framing

These dockets are not the sensitivity pass itself.

They exist to translate the challenge-round nuance into a compact feature-to-doc map so later sensitivity lanes do not have to:

- reread the whole audit corpus
- reinvent rival branch logic
- flatten weak survivors into strong doctrine

## Shared classification and launch intent

Treat this docket bundle as:

- `initial architecture research/planning`

Default launch policy:

- `gpt-5.4`
- `xhigh`

## Shared source discipline

Every docket must cite:

- the governing challenge synthesis
- the relevant challenge packet(s)
- the relevant upstream residual artifacts where needed
- the exact planning surfaces it is evaluating

Use packet/challenge outputs only as needed for that docket's feature pressure.

## Shared output purpose

Each docket must answer:

- what is the current surviving or weakened branch logic here?
- what rival still matters?
- which planning docs are affected?
- for each affected doc:
  - what is safe
  - what would overcommit
  - what would silently foreclose
  - what must remain explicit/open

## Required sections

Every docket output must explicitly include:

1. `Docket framing`
2. `Target feature pressure`
3. `Current gate classification`
4. `Current survivor and strongest rival(s)`
5. `Why this pressure matters`
6. `Relevant planning surfaces`
7. `Per-doc implication map`
8. `What each doc may safely imply`
9. `What each doc must not imply`
10. `What must remain explicit`
11. `Semantic drift watchpoints`
12. `Sensitivity lane routing`
13. `What remains open after this docket`

## Shared anti-overreach rule

These dockets must not:

- re-run the entire challenge round
- silently upgrade weak survivors into strong doctrine
- turn preserve-only or reversal-sensitive branches into dead branches
- propose roadmap commitments
