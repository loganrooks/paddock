# 05 Canon Uplift And Milestone 2 Steering Task Spec

## Task classification and launch intent

Treat this task as:

- `initial architecture research/planning`

Recommended launch policy:

- `gpt-5.4`
- `xhigh`

## Core question

What is the strongest execution-ready canon uplift we can now justify from the full gap-closure and sensitivity trail, such that:

- the canon reflects the mature-product doctrine actually earned
- Milestone 2 planning friction is materially reduced
- farther-horizon doctrine in `LONG-ARC.md` is better aligned and less dependent on audit-memory
- still-open rankings remain visibly open
- preserve-only and reversal-sensitive futures are not erased by silence

## Why this task exists

The sensitivity pass was a gate, not the true culmination.

This task exists because the current post-sensitivity framing is too narrow:

- it over-reads the round as `mostly passes`
- it under-reads the amount of mature-product doctrine the round actually produced

This task should correct that by turning the round into a stronger, file-by-file uplift proposal rather than a light cleanup recommendation.

## Required output

Write:

- `05-canon-uplift-milestone-2-steering-proposal.md`

## Output requirements

The output must include:

1. `Response framing`
2. `What the previous sensitivity verdict got right`
3. `What it understated`
4. `File-by-file uplift goals`
5. `Recommended patch order`
6. `Execution-ready patch operations by file`
7. `Milestone 2 carry-forward implications by file`
8. `Long-arc implications by file`
9. `What must stay visibly open`
10. `What must become more explicit`
11. `What the eventual patch pass must not do`

## Standard of rigor

Do not optimize for:

- minimal patch size
- easiest possible response
- `passes therefore leave mostly alone`

Optimize for:

- best durable canon expression of the doctrine earned so far
- lower future planning friction
- lower risk of re-litigating the same questions in Milestone 2
- lower risk of farther-horizon long-arc drift
- lower risk of future doc drift reintroducing bad assumptions

## Specific questions to answer

### 1. Where is the current canon still too asymmetrical?

Look for places where naming density or example choice still biases future work, especially around:

- `challenge` versus aftermath/recap
- `summary/replay` versus explicit shell and event-memory separation
- `hosted` as owner-model shorthand
- `support` / `premium` / `membership` / `priority`
- `curated` / `reviewed` / `unsupported`

### 2. What should become more explicit now?

Not because it is ready for implementation, but because leaving it implicit creates future friction.

Examples include:

- wrapper-family separation
- audience-right thresholding
- host-identity branching
- preserve-only discovery/contribution seams
- memory/cadence layer distinctions

### 3. What should remain open but more legibly open?

The proposal must not close:

- first low-burden wrapper winner
- later money-family winner
- later host-identity winner
- first mastery metric
- final event-memory surface

But it should explain how the docs can make those remain visibly open rather than merely unspoken.

### 4. How should Milestone 2 be helped explicitly?

For each file, ask:

- what future M2 work is likely to be distorted if this file stays as-is?
- what canon wording would reduce that distortion?

### 5. How should the farther long arc be protected explicitly?

For each file, ask:

- what later-horizon doctrine is currently preserved only by silence, asymmetry, or audit-memory?
- what belongs durably in `LONG-ARC.md` versus in the other canon docs?
- what wording would reduce the chance that Milestone 2 convenience quietly becomes long-arc doctrine by accident?

## Patch posture

This is a proposal task, not direct execution.

It should produce:

- execution-ready file-by-file patch intent
- not actual edits

It may recommend:

- touching `REQUIREMENTS.md`, `PROJECT.md`, `LONG-ARC.md`, `ROADMAP.md`
- leaving `01-CONTEXT.md` alone for now except for a careful rerun-time consistency touch

## Anti-overreach rules

The proposal must not:

- widen Phase 01 execution scope
- invent a new milestone
- promote preserve-only seams into active commitments
- treat sensitivity classifications as final winner-selection
- recommend canon changes that would erase challengeable branches

## Quality bar

The output should read as:

- stronger than a narrow patch note
- more concrete than a high-level reflection
- ready to drive a real canon-uplift execution pass
