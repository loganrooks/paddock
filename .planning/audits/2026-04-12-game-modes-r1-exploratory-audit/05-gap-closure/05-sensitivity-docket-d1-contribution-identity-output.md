# 05 Sensitivity Docket D1: Contribution Identity Output

## Docket framing

- Mode: `feature-to-doc translation`
- Classification: `initial architecture research/planning`
- Governing question:
  how should the core planning docs preserve the surviving middle-space pattern of `official library + Prix-controlled editorial activation + visible outside credit` without hard-coding `guest editor` as settled doctrine or flattening later `partner brand / creator profile` identity into a dead branch?
- Scope:
  - `PROJECT.md`
  - `LONG-ARC.md`
  - `REQUIREMENTS.md`
  - contribution identity and doctrine wording, not canon edits
  - middle-space preservation, not discovery-surface or unsupported-listing placement
- Non-goals:
  - not choosing final contributor namespace copy
  - not promoting `partner brand / creator profile` into active doctrine
  - not treating `reviewed submissions` or `unsupported listings` as D1-owned; those belong to `D2`
  - not deciding support, deprecation, or update ownership for activated outside packs
- Stop condition:
  each affected doc has a clear map of what it may safely imply, what would overcommit, what would silently foreclose, and what must remain explicit/open

## Target feature pressure

- `official Prix-curated library` remains the trust anchor.
- Later approved outside packs may still live inside that official library as `Prix-controlled editorial activation with visible outside contributor credit`.
- `guest editor` did not survive as locked vocabulary or finalized doctrine.
  The surviving unit is the functional pattern, not the exact label.
- `partner brand / creator profile` remains a live preserve-only rival.
  It matters most under solo ritual, creator-follow, or public-light discovery conditions, even if it is not the current default.
- The main risk is not total omission.
  It is that the core docs quietly make one of two wrong moves:
  - flatten later approved outside packs into invisible house authorship
  - or jump early to creator-platform language that over-promotes the rival branch

## Current gate classification

- Primary classification: `bounded-open`
- Embedded direct doctrine:
  - `official Prix-curated library` remains the trust anchor
- Embedded bounded-open pressure:
  - `Prix-controlled editorial activation with visible outside contributor credit`
  - exact contributor namespace such as `guest editor`, `featured author`, or similar
- Embedded preserve-only pressure:
  - `partner brand / creator profile` remains live and must not be silently killed
- Adjacent but not primary here:
  - `reviewed submissions`
  - `unsupported listings`
  - `open marketplace / public publishing`
  These stay routed to `D2` and should not be used to answer the D1 middle-space question by proxy.

## Current survivor and strongest rival(s)

- Current survivor:
  `editorial activation inside the official library` survives, but only as a functional pattern.
  The strongest surviving reading is:
  approved outside packs can be visibly credited while still being activated, curated, and presented through Prix's official trust surface.
- Strongest rival:
  `partner brand / creator profile`
  This remains preserve-only rather than promoted, but it is now a real later competitor rather than a nearly-dismissed curiosity.
- Corrective rival:
  `Prix-curated copy / delayed activation`
  If editorial review, rights handling, metadata, or maintenance load become too heavy, stronger Prix-owned curation can still re-rank upward.
- Boundary note:
  `reviewed submissions` and `directory-listed but unsupported` are not the same thing as the middle-space identity answer.
  They remain later conditional/discovery questions rather than the current contribution-identity default.

## Why this pressure matters

- Evidence:
  - `PROJECT.md:102-111` already frames Milestone 2 around more sustainable content operations, pack sharing, and reusable content/history surfaces.
  - `PROJECT.md:130-146` already says later identity and visibility seams should be preserved without widening scope, while keeping public discovery and service obligations modest.
  - `LONG-ARC.md:116-127` already says contribution and sharing questions should be staged carefully and should not silently imply open publishing or community governance.
  - `LONG-ARC.md:131-166` already keeps broad creator ecosystems deferred without calling them impossible forever.
  - `REQUIREMENTS.md:10-18`, `99-118`, and `131-143` already preserve curated content, later content operations, share/import seams, and explicit deferrals around open creator publishing.
- Inference:
  - The current canon is close to safe, but it does not yet explicitly protect the middle space between `purely Prix-authored curation` and `creator-platform discovery`.
  - If the docs emphasize only `curated/authored` language, later approved outside packs can get flattened into house-brand authorship by default.
  - If the docs emphasize only `creator` or `broad creator ecosystem` language, the preserve-only rival can get promoted into a premature identity branch.
  - D1 exists so later sensitivity can test for both failure modes instead of treating them as opposite descriptions of the same future.

## Per-doc implication map

### `PROJECT.md`

- Safe now:
  the document may keep Milestone 2 focused on sustainable content operations, pack sharing, calibration insight, and reusable content/history surfaces without deciding whether all later content is purely Prix-authored.
  It may also preserve later identity seams as future-aware possibilities rather than current commitments.
- Would overcommit:
  wording Milestone 2 or Milestone 3 so later content growth sounds like purely internal Prix authorship by default.
  Or, in the other direction, wording broader social/content surfaces as if creator-profile identity is already the honest later value center.
- Would silently foreclose:
  treating `broad creator ecosystems remain separate future decisions` as if it means later visibly credited outside contribution inside the official library is off the table.
  Or treating `curated content corpus` as if later approval automatically erases outside contributor identity.
- Must remain explicit/open:
  the official library can stay the trust anchor while later approved outside contributions remain visibly credited inside it.
  The exact label and later escalation path toward stronger creator identity remain unresolved.

### `LONG-ARC.md`

- Safe now:
  the document may keep support, access, and contribution separate, and may keep open creator publishing deferred while still preserving narrower invited/editorial contribution seams.
- Would overcommit:
  reading the current deferral of `open creator marketplace or broad public publishing` as if all contributor-facing identity beyond pure Prix authorship is deferred.
  Or treating `broad creator ecosystems remain separate future decisions` as if the only alternatives are house-only curation or a full creator platform.
- Would silently foreclose:
  collapsing the surviving middle space into one of two false extremes:
  - invisible house authorship
  - promoted creator ecosystem
  That would erase the challenge-rounded pattern of `official library plus visibly credited editorial activation`.
- Must remain explicit/open:
  there is a real middle space between `Prix-only authorship` and `creator-platform discovery`.
  `partner brand / creator profile` remains preserved rather than promoted.
  Support/update/deprecation ownership for activated outside packs is still open and should not be silently assumed.

### `REQUIREMENTS.md`

- Safe now:
  the doc may keep `PACK-*`, `OPS-V2-*`, `CONTENT-*`, `SEAM-04`, and `DEF-05` identity-neutral.
  It may preserve curated packs, authoring tools, import/share seams, and later content scaling without naming a settled contribution taxonomy.
- Would overcommit:
  adding requirement language for `guest editor`, `featured creator`, `creator profile`, `partner page`, or `reviewed submissions` as if those identities are already canon.
  Hard-coding contributor taxonomy into requirements now would outrun the challenge result.
- Would silently foreclose:
  letting `author`, `authoring`, and `curated pack` language be read as only internal Prix authorship forever.
  Or letting `open creator publishing remains deferred` be misread as `later credited outside contributions inside the official library are disallowed`.
- Must remain explicit/open:
  requirements define capability families and protected seams, not final contributor identity doctrine.
  The future may still include approved outside contributions inside official curation, while broader creator-profile discovery remains deferred.

## What each doc may safely imply

- The official Prix-curated library remains the main trust anchor.
- Later approved outside contributions may exist inside that official library with visible contributor credit and Prix-controlled activation.
- The exact contributor namespace is not chosen yet.
- The docs may keep broader creator ecosystems and open publishing deferred without implying that the middle-space contribution pattern is unavailable.
- The docs may preserve later content operations, pack sharing, and content scaling as capability families rather than as proof of a settled contributor identity model.

## What each doc must not imply

- that all later approved packs are necessarily invisible house-authored Prix content
- that `guest editor` is locked doctrine or final vocabulary
- that `partner brand / creator profile` is dead merely because open marketplace/public publishing remains deferred
- that `reviewed submissions` or broader creator discovery are already the default later path
- that support, deprecation, maintenance, or rights posture for activated outside packs is already settled
- that deferring public creator ecosystems automatically answers the narrower contribution-identity question

## What must remain explicit

- `official library as trust anchor` is stronger than any one later contributor label.
- The surviving middle-space rule is:
  `Prix-controlled editorial activation with visible outside contributor credit`.
- The label for that pattern remains open.
- `partner brand / creator profile` remains preserve-only and live, not promoted and not dead.
- `reviewed submissions`, `unsupported listings`, and marketplace/public discovery are adjacent but separate questions.
- Any later shift from middle-space editorial activation toward stronger creator-profile identity would require an explicit doctrine change rather than silent wording drift.

## Semantic drift watchpoints

- `guest editor`
  - risks sounding like settled doctrine and understating how visible contributor credit may need to be
- `creator` / `partner`
  - risks sounding like creator-profile discovery has already been promoted
- `curated`, `approved`, `featured`
  - these are not interchangeable
  - curation, moderation state, and endorsement level can differ
- `official`
  - should not automatically imply `fully house-authored` or `fully Prix-supported in every detail`
- `authoring`
  - current tooling language can accidentally erase later outside contributors if read too narrowly
- `community`
  - should not be used as a catch-all for all outside contribution, because D1 is preserving a narrower invited/editorial middle space

## Sensitivity lane routing

- Primary: `05-sensitivity-lane-i-canon-doctrine`
  - Use this docket to test whether `PROJECT.md`, `LONG-ARC.md`, and `REQUIREMENTS.md` preserve the middle-space pattern without hard-coding a final label.
- Primary: `05-sensitivity-lane-iii-preserve-reversal`
  - Use this docket to test whether preserve-only `partner brand / creator profile` remains visibly alive instead of being silently treated as dead.
- Coordination edge:
  - If the drift is really about `reviewed submissions`, `unsupported listing placement`, or `marketplace/public publishing`, route to `D2`.
  - If the drift is really about support or service ownership for activated packs, coordinate with the hosting/support dockets rather than forcing D1 to close that question.
- Secondary: `05-sensitivity-lane-iv-inquiry-debt-anti-hardcoding`
  - Use this docket to catch premature locking of contributor vocabulary or house-authorship assumptions.

## What remains open after this docket

- the exact contributor namespace for the surviving middle-space pattern
- how visible contributor credit should be inside the official library
- whether some later high-value packs should become stronger `Prix-curated copy` rather than ongoing credited outside contribution
- the trigger conditions under which `partner brand / creator profile` would re-rank upward from preserve-only to active rivalry
- support, maintenance, rights, and deprecation ownership for activated outside packs
- discovery posture, reviewed submissions, and unsupported-listing placement
  those remain for `D2`
- any canon patch or roadmap commitment
  this docket only bounds wording discipline and preserved seams
