# 05 Residual Gap Chunk Common Scaffold

## Shared framing

These chunks exist because the current `05-gap-closure` bundle is not yet ready to jump straight into the sensitivity pass.

The immediate problem is not that the remediation round failed. The problem is that:

- the remediation packets identified stronger branch families and preservation logic
- the deferral/rejection review clarified what is safely deferred, rejected-for-now, unresolved, or explicit inquiry debt
- but the broader job still has residual gaps that are too consequential to leave entirely to sensitivity

These chunks therefore exist to:

- tighten the rough shape of still-open branch families
- expose where apparent parameters still function as quiet branch selectors
- make later sensitivity analysis more honest and less overloaded
- preserve uncertainty where it is still warranted rather than manufacturing closure

## Shared classification and launch intent

Treat this chunk bundle as:

- `initial architecture research/planning`

Default launch policy:

- `gpt-5.4`
- `xhigh`

Reason:

- these are still exploratory, canon-sensitive, rerun-shaping inquiries
- the central risk is not just omission, but premature ranking, semantic drift, or false closure
- the outputs will shape what later sensitivity is allowed to treat as stable versus only preserve-only

## Shared governing inputs

Every chunk must preserve:

- the current private-first product center
- substrate-plus-wrappers posture
- layered room/group/event memory doctrine
- staged visibility and audience-right distinctions
- Round 2B non-foreclosure seams
- the remediation round's gains unless outside research or stronger comparison genuinely weakens them
- the deferral/rejection review's term distinctions:
  - `deferred`
  - `rejected-for-now`
  - `unresolved`
  - `still not sensitivity-ready`
  - `preserve-only`
  - `preferred but challengeable`

## Shared gap-justification rule

Every residual chunk spec must include a `Gap justification` section that:

- cites the exact `RGR-*` families it addresses
- cites the relevant underlying `GCO-*` entries when helpful
- explains why those residual families belong together in one chunk
- says what the chunk is not trying to close

If the chunk cannot name specific `RGR-*` anchors, it is too vague to launch.

## Shared epistemic rules

- Distinguish:
  - inherited doctrine
  - direct external grounding produced in this chunk
  - externally traceable background only
  - internal cross-artifact reasoning
  - remaining open judgment
- Do not treat repo-local packet outputs as direct external grounding.
- Use the source-basis distinctions from `review-trail-framework.md` where useful.
- Include a short `Reference translation` section:
  - what is analogous here
  - what is not analogous
  - what is borrowed as concern versus as solution
- Include a short `Negative-case / failure evidence note` where relevant.
- Do not let parameter-level cleanup silently reintroduce branch-level closure.
- If a loaded term is used differently in a source artifact than in the working review frame, flag the semantic drift explicitly instead of harmonizing it away.

## Shared output standard

Every chunk output should be:

- comparative
- explicit about uncertainty
- explicit about what it is narrowing versus what it still refuses to rank
- explicit about which unresolveds remain open but better-bounded
- explicit about what a later sensitivity pass may and may not assume

## Required sections

Every chunk output must explicitly include:

1. `Chunk framing`
2. `Gap justification`
3. `What is already settled`
4. `What remains live`
5. `Path of inquiry`
6. `Direct external source register`
7. `Reference translation`
8. `Negative-case / failure evidence note`
9. `Live alternatives`
10. `Findings`
11. `What got tighter`
12. `What remains challengeable`
13. `First-value vs later-value`
14. `Archetype-to-burden translation`
15. `Trigger conditions`
16. `Recommended carry-forward`
17. `Explicit deferrals`
18. `What should remain open`
19. `Sensitivity implications`
20. `What later residual synthesis must reconcile`

## Shared anti-overreach rule

These chunks are not trying to make the docs feel cleaner by force.

They should not:

- settle questions just because the branch vocabulary already exists
- turn preferred-but-challengeable branches into roadmap commitments
- use a polished reference to over-close a future branch family
- silently downgrade inquiry debt into preserve-only language
