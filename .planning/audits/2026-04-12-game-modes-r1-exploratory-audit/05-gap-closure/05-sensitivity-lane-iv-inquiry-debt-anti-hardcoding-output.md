# 05 Sensitivity Lane IV: Inquiry Debt And Anti-Hard-Coding Output

## Lane framing

`[governing:cited]` Lane IV is a doctrine-audit and protection pass, not a winner-selection pass. Its job is to test whether the live planning docs avoid hard-coding bounded-open questions and keep inquiry debt visible rather than faking closure (`05-sensitivity-control-note.md:21-27`, `05-sensitivity-control-note.md:80-108`, `05-sensitivity-lane-common-scaffold.md:17-31`, `05-sensitivity-lane-common-scaffold.md:44-88`).

`[governing:cited]` The challenge gate permits this lane to assume only a bounded set of things: the low-burden contest is still mostly `showcase aftermath` versus `share-by-link / challenge`; the first audience bundle is not closed and `submit / speak` is not a cheap add-on; `first explicit shell` and `first true event-memory shell` are separate; and the strongest current first explicit shell is `hosted-night recap / session report` (`05-pre-sensitivity-challenge-converged-synthesis-output.md:49-50`, `05-pre-sensitivity-challenge-converged-synthesis-output.md:62-63`, `05-pre-sensitivity-challenge-converged-synthesis-output.md:82-90`, `05-pre-sensitivity-challenge-converged-synthesis-output.md:97-112`).

`[assumed:reasoned]` The main anti-hard-coding question is not whether the current docs say anything false. It is whether repeated concrete nouns such as `challenge`, `summary`, `replay`, `spectator`, and `event` now create accidental closure by repetition asymmetry.

- `01-CONTEXT.md` as pre-rerun seam-protection input, especially its protected seams and explicit non-decisions on public challenge surfaces, persistence, and event memory (`01-CONTEXT.md:150-167`).

`[governing:cited]` This lane consumed only its assigned dockets and the gate artifact:

- `A1` low-burden wrapper ordering:
  docs must not let `challenge` naming, ladder wording, or `summary/replay` phrasing silently choose between `showcase aftermath` and `share-by-link / challenge` (`05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:147-156`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:183-199`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:236-240`).

## Direct doctrine protections

`[evidenced:cited:internal]` The live docs already protect four important doctrines correctly:

- Layered memory and cadence are explicit in canon and planning surfaces, not merely implied. `PROJECT.md`, `LONG-ARC.md`, `ROADMAP.md`, and `REQUIREMENTS.md` all preserve non-collapse across player history, room/group memory, event memory, content history, and multiple cadence layers (`PROJECT.md:142-145`, `LONG-ARC.md:60-67`, `ROADMAP.md:15`, `ROADMAP.md:186-187`, `REQUIREMENTS.md:132-135`).
- Audience readability is already separated from full audience rights in the strongest doctrine surfaces. `LONG-ARC.md` says visibility and watchability do not imply one permanent participant truth surface, and its ladder explicitly gives later spectator surfaces narrower rights than full public participation (`LONG-ARC.md:58-59`, `LONG-ARC.md:95-102`). `ROADMAP.md` also keeps `audience-only entry` distinct from player join and frames Phase 5 as readability rather than public spectator commitment (`ROADMAP.md:143-166`).
- Event/container separation is preserved. `PROJECT.md` and `LONG-ARC.md` both distinguish `event container`, `room`, and `game instance`, and `01-CONTEXT.md` keeps event/editorial wrappers as downstream consumers rather than present-tense contract choices (`PROJECT.md:48-52`, `LONG-ARC.md:50-56`, `01-CONTEXT.md:150-157`).
- Phase 1 remains explicitly non-committal on public challenge surfaces, persistence, and event-memory structures, which is the right doctrine posture for inquiry debt protection (`ROADMAP.md:52`, `01-CONTEXT.md:155-167`).

## Bounded-open anti-hard-coding findings

`[evidenced:cited:internal]` The strongest current hard-coding pressure is `REQUIREMENTS.md`, not because it is wrong, but because it names only one low-burden future concretely. `WRAP-01` and `RET-01` make `challenge` highly legible while no equivalent neutral aftermath placeholder appears alongside them, so repeated reading can make challenge feel like the chosen first reuse surface unless the A1 guardrail is carried forward explicitly (`REQUIREMENTS.md:89-102`, `REQUIREMENTS.md:124-135`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:147-156`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:236-240`).

`[evidenced:cited:internal]` `PROJECT.md` creates a milder version of the same asymmetry. Milestone 2 names `async or solo wrapper surfaces` while Milestone 3 names `spectator-facing or showcase-friendly wrappers`, so a casual reader could infer `challenge/share-by-link first, showcase later` even though the document's own open question says the first later wrapper is still pending and future visibility state remains open (`PROJECT.md:106-124`, `PROJECT.md:140-145`, `PROJECT.md:175-180`).

`[evidenced:cited:internal]` `ROADMAP.md` preserves the seam correctly, but Phase 5's repeated `summary`, `replay`, and watchable-room language is close enough to `hosted-night recap / session report` that it could be over-read as if the first explicit shell question is already effectively closed. The current carry-forward constraints prevent outright drift, but the seam is interpretively fragile (`ROADMAP.md:149-167`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:138-151`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:199-208`).

`[evidenced:cited:internal]` Audience-threshold hard-coding risk is lower, but still live anywhere `watchable`, `spectator`, or `audience-readable` appears without a rights bundle. The strongest doctrine docs already prevent this, yet none of the owned planning docs explicitly restate the A2 threshold that `watch` or light `react / vote / predict` is still a different class from `submit / speak` (`LONG-ARC.md:58-59`, `LONG-ARC.md:95-102`, `ROADMAP.md:153-166`, `05-sensitivity-docket-a2-audience-right-thresholds-output.md:137-151`).

## Preserve-only seam findings

`[evidenced:cited:internal]` `weekend board / scheduled event board` is still preserved only as a later true-event-memory seam. The live docs preserve `event container` and `race-weekend` language without yet promoting a true event object into current doctrine, which is the correct preserve-only posture (`PROJECT.md:5`, `PROJECT.md:142-145`, `LONG-ARC.md:50-67`, `REQUIREMENTS.md:95`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:186-191`).

`[evidenced:cited:internal]` Heavier spectator/showcase shells are also preserved rather than promoted. `PROJECT.md` and `LONG-ARC.md` keep later showcase/spectator wrappers alive, but they do not commit them as the next shell or as a broader public-participation default (`PROJECT.md:123-145`, `LONG-ARC.md:95-102`, `LONG-ARC.md:133-150`).

`[assumed:reasoned]` The subtle preserve-only risk is vocabulary capture: if the repo keeps using `showcase` only for the heavier later shell, then the lighter `showcase aftermath` meaning stays preserved only in the docket trail and becomes harder to see in canon. That is not yet a doctrine failure, but it is a live anti-hard-coding concern.

## Reversal-sensitive findings

`[evidenced:cited:internal]` `challenge` remains reversal-sensitive because the same noun can reintroduce three different commitments by accident: low-burden share-by-link replay, recurring/programmed cadence, or visible result shell. `REQUIREMENTS.md` and `PROJECT.md` keep the noun live, and `LONG-ARC.md` places it on the visibility ladder, so future wording must not let one sense quietly overwrite the others (`PROJECT.md:140-145`, `LONG-ARC.md:95-102`, `REQUIREMENTS.md:89-102`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:183-216`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:199-205`).

`[evidenced:cited:internal]` `summary`, `replay`, `featured`, and `weekend` remain reversal-sensitive because they can smuggle `first explicit shell closed` or `event object present` back into the docs. The live roadmap keeps them bounded correctly, but the E1 and E2 dockets both identify these terms as the most likely path back into premature shell or event-memory commitment (`ROADMAP.md:149-187`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:142-151`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:193-208`, `05-sensitivity-docket-e2-event-memory-cadence-mastery-output.md:151-171`, `05-sensitivity-docket-e2-event-memory-cadence-mastery-output.md:173-188`).

`[assumed:reasoned]` `audience` also stays reversal-sensitive in a narrower sense: no owned doc currently claims stronger interactive rights, but any future use of `interactive audience` without naming the allowed rights bundle would immediately reintroduce the rejected shortcut that `submit / speak` is just a cheap add-on.

## Inquiry-debt protection findings

`[evidenced:cited:internal]` The exact low-burden order is still open. The current docs preserve that indirectly, but they do not restate it directly, which is why challenge-only naming remains the biggest anti-hard-coding risk (`PROJECT.md:175`, `REQUIREMENTS.md:89-102`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:194-199`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:236-240`).

`[evidenced:cited:internal]` The first audience bundle is still open. The owned docs preserve audience seams and role separation, but they do not yet carry the sharper threshold that `submit / speak` may indicate a different shell rather than a later in-family bundle (`ROADMAP.md:143-166`, `LONG-ARC.md:58-59`, `05-sensitivity-docket-a2-audience-right-thresholds-output.md:145-151`, `05-sensitivity-docket-a2-audience-right-thresholds-output.md:179-185`).

`[evidenced:cited:internal]` The boundary between `room recap`, `hosted-night recap`, `featured challenge result`, and true `event memory` is still open. `ROADMAP.md` and `REQUIREMENTS.md` correctly preserve `summary/replay` and layered history, but the E1/E2 dockets show that permanence, visibility, and object-threshold questions remain unresolved even when the current wording is safe (`ROADMAP.md:149-187`, `REQUIREMENTS.md:99-102`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:186-191`, `05-sensitivity-docket-e2-event-memory-cadence-mastery-output.md:160-171`, `05-sensitivity-docket-e2-event-memory-cadence-mastery-output.md:208-214`).

`[evidenced:cited:internal]` Permanence depth, visibility/navigation depth, cadence taxonomy, and first mastery read remain open by doctrine. The docs preserve layered structure, but they should not be read as having chosen one archive depth, one cadence vocabulary, or one player-mastery metric (`PROJECT.md:142-145`, `LONG-ARC.md:60-67`, `ROADMAP.md:186-187`, `05-sensitivity-docket-e2-event-memory-cadence-mastery-output.md:151-171`).

`[evidenced:cited:internal]` `01-CONTEXT.md` is currently the safest surface in this lane because it keeps these questions downstream: public challenge surfaces, persistent identity, room/group memory, and event-memory structures all remain explicit non-decisions for Phase 1 (`01-CONTEXT.md:155-167`).

## Semantic drift findings

`[evidenced:cited:internal]` `challenge` is the highest-drift term in the owned docs. It currently spans at least three pressures across canon and dockets:

- low-burden share-by-link or replay surface (`PROJECT.md:140`, `REQUIREMENTS.md:89`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:194-199`)
- recurring/programmed cadence (`REQUIREMENTS.md:99`, `PROJECT.md:143`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:155-156`)
- result-shell or event-adjacent language (`LONG-ARC.md:99`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:199-205`)

`[evidenced:cited:internal]` `showcase`, `spectator`, `audience`, and `watchable` also carry different burdens in different docs:

- low-burden aftermath meaning survives mainly in docket A1, not in canon (`05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:196-198`, `05-sensitivity-docket-a1-low-burden-wrapper-ordering-output.md:203-205`)
- heavier spectator/showcase shell meaning appears in `PROJECT.md` and `LONG-ARC.md` (`PROJECT.md:123-145`, `LONG-ARC.md:99`, `LONG-ARC.md:133-137`)
- watchability in canon means shared legibility, not interaction rights (`PROJECT.md:138`, `ROADMAP.md:153-166`, `05-sensitivity-docket-a2-audience-right-thresholds-output.md:153-166`)

`[evidenced:cited:internal]` `event`, `featured`, and `weekend` remain the main cross-docket drift cluster for shell and memory doctrine. `PROJECT.md` and `LONG-ARC.md` use `event container` as a higher-level shell, `REQUIREMENTS.md` uses `race-weekend` as themed-pack texture, and the E1/E2 dockets warn that none of those uses alone prove a true event object or a first explicit shell (`PROJECT.md:48`, `LONG-ARC.md:50-56`, `REQUIREMENTS.md:95`, `05-sensitivity-docket-e1-first-explicit-shell-output.md:195-206`, `05-sensitivity-docket-e2-event-memory-cadence-mastery-output.md:175-186`).

`[evidenced:cited:internal]` Shared drift checks outside the A/E family were also run on the owned docs:

- `hosted`, `operator`, `hybrid`:
  no new IV-lane hard-coding was found. The owned docs keep private-host and operator language bounded and do not silently choose a hosting branch here (`PROJECT.md:139`, `ROADMAP.md:80-100`, `LONG-ARC.md:106-114`).
- `support`, `premium`, `membership`, `priority`, `reserved`:
  no new IV-lane drift was found. `PROJECT.md` and `LONG-ARC.md` explicitly keep paid guaranteed access and stronger service promises out of current doctrine (`PROJECT.md:146`, `LONG-ARC.md:118-129`).
- `creator`, `partner`, `reviewed`, `unsupported`, `marketplace`:
  no new inquiry-debt conflict was created in the owned docs. Where these terms appear, they remain deferred or historical, and their live classification should stay with the sibling preserve/reversal lanes (`ROADMAP.md:184`, `LONG-ARC.md:161`, `REQUIREMENTS.md:151`).

## Concrete doc adjustments or carry-forward notes

`[projected:reasoned]` No direct canon edits are warranted inside this lane artifact. The current docs are mostly safe, but converged synthesis should carry forward these notes:

- Protect `WRAP-01` and `RET-01` with an explicit reading that they are illustrative future capability families, not proof that `challenge` has already beaten aftermath/recap.
- If a canon patch is later needed, the most useful target is not a big rewrite. It is a small neutral reminder, likely near `PROJECT.md` future-wrapper language or in the sensitivity synthesis, that the first low-burden post-private wrapper remains open between aftermath and share-by-link/challenge.
- Keep Phase 5 `summary/replay` phrased as room closeout adjacent to later recap/report thinking, not as an already-chosen outward shell or event-memory object.
- When future docs use `audience`, specify the rights bundle. When future docs use `event`, `featured`, or `weekend`, specify whether the meaning is cadence packaging, explicit shell, or true event object.
- Keep `01-CONTEXT.md` non-decisions intact in the next rerun. Phase 1 should continue to preserve substrate only.
