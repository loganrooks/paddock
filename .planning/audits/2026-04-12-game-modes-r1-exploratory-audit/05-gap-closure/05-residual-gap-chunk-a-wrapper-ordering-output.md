## 8. Negative-case / failure evidence note

`[evidenced:cited:external-direct]` The outside sources repeatedly show that the burden rise is real, not theoretical:

- GeoGuessr lets hosts kick live-challenge players, ban from private parties, and remove challenge leaderboard entries
- Kahoot warns against sharing live PINs publicly, adds `2-step Join` so only people who can see the host screen can enter, and recommends locking entry once expected players are in
- Jackbox ships moderation, passworded rooms, room-code hiding, Twitch-linked identity, and kick controls because public or semi-public audience access predictably creates troll and safety problems
- Discord Stage puts everyone into a muted audience by default and requires moderator approval for speaking; Discord Community and Discovery add verification, rules, moderation channels, and discoverability requirements
- Mastodon explicitly treats discoverable public-service operation as something that requires moderation, backups, emergency access, and shutdown notice

`[assumed:reasoned:internal+external-direct]` This negative evidence means:

- `bounded live audience` is real, but not low-burden in the same way that recap or link challenge is low-burden
- `ambient community` is not just a bigger audience shell
- once official programming becomes globally visible and recurring, it starts borrowing some burden from editorial operations and public-facing trust surfaces even if it does not yet become full community

## 9. Live alternatives

### 9.1 `Showcase aftermath`

`[evidenced:cited:internal+external-direct]` This remains a real wrapper family.

Direct external grounding:

- GeoGuessr challenge creators can run public leaderboards, anonymize nicknames, and remove results from the results view

Interpretation:

- this is a `read-after` family:
  - standings
  - reveal memory
  - rivalry trace
  - session recap
- it creates low-burden value for recurring groups without requiring deferred participation or public service identity

### 9.2 `Share-by-link / challenge`

`[evidenced:cited:internal+external-direct]` This remains a real wrapper family.

Direct external grounding:

- GeoGuessr `Play with Friends` groups private lobby and URL-shared challenge together, but still treats challenge as distinct from private lobby
- GeoGuessr also supports invite-only challenge flows
- Kahoot assignments are explicitly self-paced, not host-presented live, and are shared by PIN, link, or QR

Interpretation:

- this is a `play-later / replay-later` family
- it is the clearest first-value extension for:
  - private online sync
  - schedule-mismatched friend groups
  - solo ritual with shared comparison

### 9.3 `Bounded live audience`

`[evidenced:cited:internal+external-direct]` This remains a real wrapper family, not just a stronger audience bundle.

Direct external grounding:

- Jackbox separates player count from audience support and documents remote play through screen share or streaming
- Discord Stage defaults members to muted audience, then lets moderators approve speaking
- Kahoot live play is explicitly host-screen-gated and uses live-only join protections

Interpretation:

- this is the first credible `watch-live / hosted-event` family
- it is strongest for bounded event shells
- it is not the global first answer for every archetype

### 9.4 `First audience bundle`

`[evidenced:cited:internal+external-direct]` This does **not** currently look like a missing wrapper family. It looks like an ordering question *inside* the `bounded live audience` family.

Direct external grounding:

- Discord Stage starts with `view + listen` by default, then adds `request to speak` only through moderator approval
- Jackbox shows materially different audience bundles:
  - vote
  - like
  - predict
  - submit text
  - influence outcomes

Interpretation:

- the evidence supports a staged audience-bundle ladder inside one family:
  1. `watch / read live`
  2. `react / vote / predict`
  3. `submit or speak`
- that is a useful narrowing, but it does not justify a final first bundle yet

### 9.5 `Daily/programmed challenge`

`[evidenced:cited:internal+external-direct]` This does **not** look like a peer wrapper family on the same level as `showcase aftermath`, `share-by-link / challenge`, or `bounded live audience`.

Direct external grounding:

- GeoGuessr Daily Challenge is a centrally run same-round global competition
- Kahoot distinguishes self-paced assignment and solo play as the reusable primitives; official programming sits on top of those content/session surfaces rather than replacing them with a new core session shape

Interpretation:

- `daily/programmed challenge` is primarily `editorial-adjacent`
- it usually rides one or both of:
  - challenge/self-paced wrapper
  - solo ritual / self-practice wrapper
- it may later create additional recurrence, leaderboard, and memory pressure
- but it should not currently be treated as a separate first-wrapper family

### 9.6 `Ambient community later shape`

`[evidenced:cited:internal+external-direct]` This remains a true distinct later branch family.

Direct external grounding:

- Discord Community and Discovery require safety checks, rules surfaces, moderation channels, and discoverability setup
- Discord Discovery makes a server public and visible to all, with eligibility thresholds and moderation requirements
- Mastodon frames public-service operation as involving moderation work, community management, backups, emergency access, and shutdown notice

Interpretation:

- `ambient community` is not recap
- it is not ordinary challenge sharing
- it is not merely bounded audience
- it is a persistent, discoverable, moderation-bearing service branch

## 10. Findings

1. `[evidenced:cited:internal+external-direct]` The current wrapper family map is mostly sound. The remaining uncertainty is now mostly about ordering, not undiscovered wrapper families.
2. `[evidenced:cited:internal+external-direct]` `First audience bundle` is a staged capability question inside `bounded live audience`, not a missing peer family.
3. `[evidenced:cited:internal+external-direct]` `Daily/programmed challenge` is better classified as an editorial/programming layer over challenge or solo primitives than as a peer post-private wrapper family.
4. `[evidenced:cited:internal+external-direct]` `Bounded live audience` remains a true branch family because it changes session shape, join control, moderation posture, and host responsibility in ways recap/challenge do not.
5. `[evidenced:cited:internal+external-direct]` `Ambient community later shape` is unquestionably a later branch family, not a larger version of audience or showcase.
6. `[assumed:reasoned:internal+external-direct]` The remaining global first-wrapper problem is therefore:
   - mostly a low-burden ordering question between `showcase aftermath` and `share-by-link / challenge`
   - plus an archetype-specific decision about when `bounded live audience` becomes worth paying for

## 11. What got tighter

`[evidenced:mixed:internal+external-direct]` This chunk tightens the picture in five ways:

- it converts `first audience bundle` from a vague open question into a staged bundle-order question

- it reinforces that `showcase aftermath` and `share-by-link / challenge` are still separate low-burden families
- it clarifies that the remaining `global first-wrapper` tension is mostly archetype ordering, not family discovery

## 15. Trigger conditions

Promote `showcase aftermath` if:

- recurring groups revisit standings, reveals, screenshots, or rematch bragging
- low-burden recap would clearly add value before deferred participation would

Promote `share-by-link / challenge` if:

- absent-friend rivalry or schedule mismatch appears often
- solo or small-group replay matters more than public watchability
- authored packs are strong enough to survive deferred replay

Promote `bounded live audience` if:

- hosted nights or bounded event shells become repeated demand
- hosts can manage audience access and moderation
- watch-live reveal energy matters more than time-shift flexibility

Promote the first interactive audience bundle only if:

- passive watchability proves too thin inside a bounded audience shell
- the project can support at least lightweight moderation and promotion/demotion control

Promote `daily/programmed challenge` if:

- the project has an official authored cadence worth repeating
- same-round comparison across people or across days is part of the value proposition
- editorial operations are strong enough to sustain fairness and recurrence clarity

Promote `ambient community later shape` only if:

- the project deliberately wants persistent discoverability
- it is willing to take on moderation, safety, backup, and service-identity obligations
- it is willing to separate official/community spaces from bounded audience or recap surfaces

## 16. Recommended carry-forward

`[assumed:reasoned:internal+external-direct]` The best carry-forward after this chunk is:

- keep the current family split
- treat `showcase aftermath` and `share-by-link / challenge` as the two main low-burden first-value candidates
- treat `bounded live audience` as the true first live public-adjacent family, mainly for bounded event shells
- treat `first audience bundle` as a staged ordering question inside that family
- treat `daily/programmed challenge` as editorial-adjacent, layered on challenge/solo primitives rather than as a new peer family
- keep `ambient community later shape` reserved for a later discoverable service branch
