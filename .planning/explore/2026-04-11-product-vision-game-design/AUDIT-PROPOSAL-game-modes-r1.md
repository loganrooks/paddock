## What I think this audit is

This should be treated as a `no named subject × exploratory × self` audit for Round 1.

- no named subject because the work is not just "analyzing a corpus of artifacts"; it is using the current game-mode writeups as launch points for a broader design-space inquiry, and the most important subject may only become clear once the exploration is underway
- `exploratory` because the brief explicitly rejects checklist evaluation, yes/no questions, and premature closure, and instead asks for expansion, surprise, gap-finding, and new material
- `self` because this first round is tightly coupled to the live exploration context and benefits from keeping the reading, critique, and creative synthesis in one place rather than adding delegation drift

Named subjects can still come online locally when useful:
- `artifact_analysis` when grounding a claim in what the existing docs actually contain
- `comparative_quality` when contrasting the portfolio against BoxBoxd or other F1 fan game shapes
- light `process_review` notes only if the current framing itself appears to be hiding a design territory that should be opened

## Proposed method

### 1. Initial orientation

Establish the current portfolio shape before judging individual ideas:
- what kinds of play are already present
- what kinds of F1 fandom are being served
- where the current material is most differentiated from BoxBoxd
- what overall taste/profile the brainstorming already demonstrates

This initial orientation should also explicitly resist two bad assumptions:
- that there is one ideal F1 fan the whole portfolio should target
- that every mode should be judged by the same appeal logic

### 2. What is already here

Read the current modes as **families of possibilities**, not as finished game pitches:
- what is already designed versus what is still only a seed
- what mechanical or social directions are already implicit in each family
- where the current writeups are concrete enough to support critique
- where they are still mostly flavor and need expansion before they can be judged
- which ideas have already been pressure-tested more directly by the user, and which have not yet really been interrogated in conversation

### 3. Possibility expansion

For each mode family, go beyond the immediately listed form:
- what other variants or round types does the core idea naturally afford
- what adjacent mechanics or combinations are implied but unstated
- what hidden versions of the same mode might serve totally different moods or groups
- what the mode becomes if pushed toward competitive, chill, chaotic, cerebral, social, or accessible play

### 4. Mode map

Build a compact internal map of the current portfolio by:
- core mechanic
- social shape
- required F1 literacy
- energy level
- replay driver
- content burden
- context profile
- context tensions
- interesting context-overflow / hybrid potential

This is how I avoid treating each mode as an isolated blob while still preserving the fact that each one may have multiple viable forms.

### 5. Mode-by-mode exploratory audit

For each mode family, I would cover:
- what is already strong and specific
- what feels generic, thin, or over-dependent on flavor text
- what adjacent variants the current concept naturally opens
- which player types or session contexts it currently serves best
- how it could be tuned toward a specific type of player without breaking the idea
- how it could be tuned toward broader appeal through difficulty levels, variants, or configuration
- where the same core mechanic could plausibly support both niche and broad appeal
- what its replayability actually depends on
- what should be flagged for later research instead of prematurely decided now

This section should avoid yes/no verdicts like "will F1 fans like this?" The better question is: **what kinds of play does this mode enable, for whom, under what tuning, and with what replay logic?**

### 5.5 Additional audit lenses

There are a few categories the current exploration has touched, but not yet applied systematically across the portfolio. Round 1 should explicitly use them:

- **Mode capability lens**
  For each mode: what is it best at supporting now?
  Categories to test:
  - local couch multiplayer
  - private online sync
  - online async
  - hybrid local+remote
  - solo practice / challenge play
  - spectator / stream view
  - community authoring / remix potential

  These are heuristics, not a prison. The audit should also notice when a mode exceeds this grid in an interesting way rather than forcing it back into the listed buckets.

- **User situation lens**
  Instead of one generic "player," test modes against distinct situations:
  - 4 friends on a couch, mixed F1 knowledge
  - 2 hardcore fans + 2 casual partners
  - remote Discord group looking for synchronous play
  - solo fan killing 10 minutes between race weekends
  - watch-party crowd with spectators who are not actively playing every round
  - recurring friend group that wants persistent inside jokes / history

- **Context profile / tension map**
  Not every mode needs to support everything, but the audit also should not assume each mode has one central "true" context.
  For each mode, the audit should identify:
  - where it is clearly strong
  - where it can plausibly balance two or more contexts well
  - where different variants of the same mode could make different context commitments
  - where contexts genuinely tension against each other and one good version may exclude another
  - where support for a context would feel forced and probably should not be optimized

  This matters because some strong games are single-context specialists, some are dual-context hybrids, and some want to fork into distinct variants rather than pretend one version can do everything.

- **Community / online potential**
  The audit should ask:
  - does this mode want friend-group history?
  - does it want public competition?
  - does it want user-generated content?
  - does it create good spectator moments?
  - does it benefit from calendar/event cadence?
  - does it have a plausible async form, or is async a distortion?

- **Launch-gap lens**
  Before launch, likely underexplored categories to explicitly check:
  - onboarding / learnability
  - session-length fit
  - drop-in / drop-out resilience
  - mixed-skill-group friendliness
  - spectator boredom / elimination dead time
  - content supply burden
  - moderation / safety needs where player-generated or public-facing
  - whether a mode is funny once versus structurally replayable
  - whether the category grid itself is missing a play shape this mode reveals

### 6. Portfolio synthesis

After individual reads, I would step back and explicitly test for:
- missing mechanic territories
- missing social configurations
- missing energy levels
- missing audience segments
- weak session-arc composition across a party night
- weak differentiation versus BoxBoxd or generic "X but for F1" cloning
- whether the portfolio has the right balance between **virality hooks** and **return loops**
- whether the portfolio covers a healthy plurality of **user situations** rather than assuming one dominant way of playing
- whether modes are being over-optimized for universal compatibility instead of being honest about their real context tensions
- whether the current category grid is itself too narrow for the most interesting modes being imagined

### 7. New proposals

I would add new proposals only where they do one of two things:
- fill a real portfolio gap
- clearly outperform an existing weak/flat direction

The goal is not to pad the list. The goal is to produce a tighter and more interesting portfolio.

### 8. Reflexivity / edge handling

The output should explicitly name:
- what this audit's creative-exploratory frame cannot settle
- what architectural or legal questions were intentionally held open
- which findings are strongest versus still only promising hunches

Architectural pressure should appear only as a secondary note when a mode would obviously change the substrate assumptions. It should not drive the round.

### 9. Round structure

I think this should be treated as **an iterative loop with at least two rounds**, not as a one-shot definitive audit:

- Round 1: initial orientation, expansion, critique, portfolio synthesis, and first-wave new proposals
- creator feedback: you react to what landed, what missed, what felt wrong, and what deserves deeper pursuit
- Round 2: revisit the original ideas plus the newly generated material together, now with sharper comparative judgment and self-evaluation
- Later rounds if needed: continue until the judgments, recommendations, and new directions feel stable enough to trust

That matches your stated intent better than pretending this first pass should close the question.

### 10. Recommended execution model

I do **not** think this should be run as one detached single-agent pass.

I also do **not** think it should be split into one lane per mode. Too many of the modes are still families of possibilities rather than finished designs, and some of the most useful judgments will only emerge through cross-mode comparison.

My recommendation is a hybrid:

- keep **root framing, orientation, and final synthesis** centralized with me
- parallelize only the heavy exploratory middle
- group only by **shared interaction model and shared audit questions**

The reason to group at all is not "these modes are basically the same." It is narrower:
- a grouped lane can compare nearby ideas against each other
- it can reuse the same evaluative questions across multiple modes
- it avoids wasting time re-deriving the same judgments mode by mode

Bad grouping creates false equivalence. So the grouping should stay **provisional during Round 1 rather than being over-locked up front**.

Current best-guess Round 1 bundles, subject to revision as Round 1 sharpens:

1. **Authored prompt / reveal modes**
   Likely scope: `Words of Wisdom`, `Sound-based Games`
   Shared audit questions: content sourcing, reveal structure, round variety, replayability from authored material versus player variation

2. **Judgment / decision modes**
   Likely scope: `The Stewards' Room`, `Team Principal's Desk`, `Relive the Moment` as a content lens rather than a separate mode
   Shared audit questions: quality of partial-information decisions, debate payoff, expertise floor, whether the "real answer" strengthens or weakens the game

3. **Player-generated expression modes**
   Likely scope: `Paddock Fashion`, `Meme Prompts`
   Shared audit questions: whether the players truly become the content, prompt quality, accessibility, repeatability, and whether the mode creates good reveals rather than just funny premises

4. **Real-time action / chaos modes**
   Likely scope: `Pit Stop Co-op`, `The Verstappen Game`, `Talibantonelli / Osama bin Russell`
   Shared audit questions: whether the core loop is actually fun versus merely funny in concept, round length, elimination/spectator design, how vehicle ladders / unlocks / challenge modes affect replayability, and what later research should be parked rather than prematurely decided

5. **Information-asymmetry / cooperative reasoning**
   Likely scope: `The Grid Walk`
   Note: this may deserve standalone treatment because it is structurally different from the rest of the current set

If the Round 1 work shows these bundles are wrong, I would rather change them than defend them.

### 11. New-game generation strategy

I think we **should** weave a first wave of entirely new-game brainstorming into Round 1, but in a bounded way.

Why:
- if we wait until Round 2 to generate new territory, Round 1 may overfit to the current brainstorm
- if we do too much new ideation in Round 1, the audit loses discipline and becomes an unbounded brainstorm

So my recommendation is:

- Round 1 should include a **bounded first-wave new-territory pass**
- each grouped lane can generate a small number of stronger adjacent or gap-filling proposals
- the centralized synthesis then chooses which of those deserve to survive into the next round

Then in Round 2:
- revisit the original modes
- revisit the best new proposals from Round 1
- incorporate your feedback on both
- generate more only where the second pass reveals genuine missing territory

## Planned standards

- cite specific passages from the source docs when making claims about what was or was not already brainstormed
- distinguish strong design primitives from mere theme dressing
- avoid feasibility collapse, but still flag when a mode's appeal depends on unresolved research
- prefer sharper critique over polite cataloging
- generate fewer, stronger additions rather than many thin ones
- avoid yes/no judgments where the better output is "this concept becomes interesting under these conditions or variants"
- treat audience fit as one lens among several, not the single standard every mode must satisfy in the same way
- explicitly distinguish **shareability/virality** from **replayability/retention**, so memey modes are not overcredited for being funny once and serious modes are not undercredited for building long-term engagement
- explicitly distinguish **context strengths**, **context tensions**, and **variant forks**, so the audit does not accidentally force every mode into one central context or into universal compatibility
- treat **user-origin and conversation depth** as a signal of prior pressure-testing, not as a proxy for quality or priority
